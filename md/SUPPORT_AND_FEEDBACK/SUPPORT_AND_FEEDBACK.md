# Overview

This document defines the bounded support and feedback strategy for the first public release and the immediate post-publication stabilization phase.

The support infrastructure intentionally prioritizes:

* trust-oriented communication,
* calm human interaction,
* supportability-first operational flow,
* bounded support complexity,
* publication-safe feedback handling,
* deterministic issue reconstruction,
* emotionally lightweight communication,
* actionable runtime diagnostics,
* sustainable solo-maintainable operations.

The project intentionally avoids:

* enterprise-scale support systems,
* manipulative retention support,
* AI-generated fake empathy,
* aggressive engagement follow-ups,
* dark-pattern review interception,
* support automation overload,
* psychologically coercive feedback funnels,
* opaque support escalation.

The support strategy intentionally optimizes for:

```text
calm trustworthy user communication
```

instead of:

```text
maximum engagement extraction
```


```text
→ organic reviews
```

# Recommended Review Flow

Publication-safe review direction:

* occasional calm rating request,
* only after stable usage,
* never during frustration states,
* never after failures,
* never during recovery runtime,
* never during onboarding overload.

Preferred review wording:

```text
If the app feels useful, you can leave a review.
```

Avoid:

* “Rate us 5 stars!”
* “Support the project now!”
* “Help us grow!”
* emotionally coercive requests.
